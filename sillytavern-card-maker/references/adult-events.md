# 成人卡 · 事件与演出系统设计

> 何时读：制作/修改含成人情节的卡；或用户反馈「事件两三句话就结束 / 围观群众抢戏 / 数值随演出膨胀或纹丝不动 / 每场触发太稀」等问题时。以下配方均在实战卡中验证过。

## 1. 演出时长控制（防速通）——解决「事件只有两三句话」

**根因**：规则里只写「多写几个来回」时，模型会把整场压缩进一楼——「来回」必须显式绑定到**楼层**才有约束力。

做法（写成一个独立条目，蓝灯 @D0，示例名「遭遇导演术」）：

- **回合口径**：一楼 = 一次 AI 回复；一个来回 = 一楼 + 玩家一次回应；下文一律按楼计。
- **每楼一个节拍**：节拍 = 对方的「一个动作＋主角反应＋环境变化」；手搭上腰是一拍，揉捏是下一拍——不跳步。
- **楼尾切在「未完成」处**：手刚搭上、话说到一半、车门正在关。禁止以完结句收楼（「他走了」「结束了」「一切恢复平静」）。
- **时长下限表**（未被中断时的硬基准，上不封顶；同时命中取大者）：试探 ≥2 楼 / 轻度 ≥4 / 中度 ≥6 / 重度 ≥10 / 完整性爱过程 ≥12~15（跨场景合并、不重新计时）/ 调教场次 ≥6。
- **玩家可提前结束**（有效反抗、脱身、报警）——但结束也要过程（对峙、代价、余波）；「继续」类回应不是加速指令。
- **防速通规则**：禁一句话总览整场、禁「几分钟后/后来」跳时间、禁预支后续档位。
- 开场白与示范要**演示**该节奏（结尾悬空，不解析）。
- 其他叙事场景照旧短促，只有事件场景走慢节奏——在文风条目里注明「例外」。

## 2. 事件构成与边界（搭讪 ≠ 骚扰）

- 写明**构成比例**：直接上手的骚扰约占 4/5；纯搭讪（只动嘴、目的是认识）约占 1/5。
- 给出**边界定义**：只动嘴、目的是认识＝搭讪；手先到位（哪怕「无意」的擦碰）＝骚扰——「动手的搭讪」归骚扰。
- 单独给「搭讪档」一个稀有子类，注明「只到认识为止、不主动动手」，并写明「不要连续多场都碰上只想认识的人」。
- 反例警示：别把大多数遭遇写成「先聊两句」——话术是幌子，不是流程。

## 3. 触发密度：下限不是间隔；允许连续触发

- 把「平均每 N 次场景切换至少一次」明确为**下限，不是间隔**。
- 明示「**触发次数不设上限**——连续触发、同一天连场、上一场刚收束就再来一场都照常判定；不要人为留间隔，不要因为『刚发生过』而缓手」。
- 给出连场写法清单：同一场景里一场接一场、换个人接力、刚脱身又被贴上。
- 防重复只约束**素材**（如「同一条目至少隔 3~5 场戏，换一条即可」），**不构成触发间隔**。

## 4. 计分护栏：演出拉长 ≠ 数值涨速

- 累积型变量（堕落/依存类）改为**完整事件结束时一次性结算**——事件进行中的每一楼都不加。
- **分档 + 单次封顶**：试探 +1 / 轻度 +2 / 中度 +3 / 重度 +4 / 大型多档事件 +5；单次结算封顶 +5。
- 未走完的事件低结算（+0~1）；速通式一句话事件照最低档 +1（不许纹丝不动）。
- 沉默、身体诚实反应、事后合理化等追加项**并入档位**，不层层叠加。
- 独立小结算单独列（如目击 +1、关键转折 +3~5），同样受一次性封顶约束。
- 即时型数值（性欲/快感）保留渐进涨落，但配冷却/回弹规则。

## 5. 镜头聚焦（防围观群戏）

- 显式规则：「镜头只跟主角与正在对手戏的人；旁人、路人、环境都是背景板——最多一两笔（装睡、移开视线、报站声），不给特写、不写群像心理。」
- 改写细节引导词：把「旁边的人在干什么」换成「对方呼吸和动作的节奏——细节给主角和下手的人」。
- 围观者只作功能性使用：某人的沉默、某次差点出手又缩回——稀有一笔，不当主戏写。

## 6. 色情事件库模式（丰富 + 可触发）

- **五类库**结构，各做一个常驻条目：骚扰情境 / 性爱玩法 / 调教 / 排解 / 其他（影像·围观·暴露·特殊场所）。
- **总则条目**统管四件事：分类表（谁触发、从哪个库取）、投放规则（每场落库 1~3 条当骨架；按「地点×时段×人物×变量」抽取；短期不重复）、**触发保障**（「库不许闲置」：弱遭遇也至少落一条起手式；戏进入性行为就必须看得见对应玩法在演……）、分类边界（防串库：排解房间里没有别人等）。
- 一切进入性行为的场景都从对应库取玩法；**库＝素材下限**——可以现编，但不得比库更收敛、更单薄。
- 玩家 OOC 点名玩法时，从其所属库取最接近的条目执行。

## 7. 用词条款：直白、粗俗、按场景选语域

### 7.1 三条硬规则

- 性器官、性行为、体液、快感/高潮/射精/潮吹一律点名直说，不写“下面、那里、私处、花径、蜜液、玉峰、分身、禁地”这类代称。
- **宁可粗俗，不许含蓄**；不要用诗意比喻替换器官或动作，也不要用“一阵云雨”“春潮”概括性交。
- 语域由场景决定：同一场戏先定一个主导语域（医学 / 民间粗俗 / 日系色情），不要每句随机换；角色对白可按人设切换，但旁白保持主导语域。

### 7.2 三套语域

| 语域 | 适用场景 | 器官/动作示例 | 语感 |
|---|---|---|---|
| 医学/临床 | 妇科检查、受孕/妊娠/临盆、伤病、解剖断面、系统播报、冷静旁观 | 阴道、阴道壁、宫颈、子宫、阴蒂、阴唇、肛门、阴茎、龟头、精液、射精、高潮 | 准确、冷、去羞耻 |
| 民间粗俗 | 粗野性爱、脏话、支配/羞辱、乡野/军营/奴隶场、醉酒/失控 | 屄、逼、鸡巴、屌、奶子、奶头、屁眼、骚水、精液、射在里面 | 糙、脏、直接 |
| 日系色情 | 日式/ACG 设定、eroge/AV 风格、用户使用日系词、调教/雌堕/中出/潮吹桥段 | 膣内、膣壁、子宮口、亀頭、肉棒、雌穴、中出し、潮吹き、絶頂、愛液 | 二次元、类型化、镜头感 |

中文卡里的日系词可以用汉字/借词（膣内、子宮口、亀頭、中出、潮吹、绝顶），不必整句日文；保持角色语言可读。

### 7.3 怎么选

- 医疗/检查/怀孕/分娩/解剖/系统面板 → **医学**。
- 粗野交合、脏话、权力差、羞辱、乡野/军营/奴隶场 → **民间粗俗**。
- 日式/二次元/eroge、用户用“膣/中出/潮吹”等词、或角色是日系人设 → **日系色情**。
- 不确定时：旁白用医学或民间粗俗（按角色阶层/场景粗粝度），对白跟角色；不要用“花径/蜜液”这种半文半白的委婉词。
- 同一场戏允许因 POV 变化切换一次语域（如系统播报医学、角色对白粗俗），但不要每句换一套。

### 7.4 禁止清单

以下词禁止作为器官/动作的**唯一指代**：

`花径、蜜液、玉峰、分身、下面、那里、私处、禁地、花心、玉茎、幽谷、甬道、花瓣、云雨、翻云覆雨`

- 角色对白可以因羞耻/身份而含糊，但旁白必须给出明确所指；不能整段只靠对白含糊带过。
- `蜜穴、肉穴、雌穴、骚穴` 在粗俗/日系语域里算明确词，不算委婉；医学场景仍用医学词。

### 7.5 演出密度与检查

- 声音 / 湿痕 / 语言三线并进；一个来回写足三到五句起，不许一句话概括；性场景不受“单段不超过四句”约束。
- 输出前抽三段自检：每段是否至少有一个明确的器官/动作词；是否出现禁词；语域是否一致；是否用比喻替代了动作。

## 8. 质检脚本：轻量提示模式（不阻断）

- 模式：监听 `message_received`，对最新回复做启发式检查——如「含性词却缺声景/湿痕」「很短却同时出现接触描写与收尾词 = 疑似速通」→ `toastr` 温柔提示「可重 roll，或用 OOC 按某条目补写」。
- 纪律：只提示、不改任何内容；阈值放宽容忍误报；说明文档写明「可在酒馆助手里禁用该脚本」。参考实现：卡工程 `scripts/场记提醒.js`。

## 9. 主角人设不预设（除非用户点名要固定人设）

- 人设字段默认留空：schema 默认 `''`＋更新规则「只采纳玩家提供的内容（表单/档案/正文），没给就保持空白，绝不代填、绝不发明」。
- 老存档迁移：读到旧版卡内默认文案时自动清空（自定义值保留）。
- 创角表单占位符不得暗示默认人设（写「可留空：不预设」）。
- 叙事规则：「性格、背景、腔调都属于玩家——一切以玩家档案与写法为准；卡内设定与档案冲突时以玩家为准」。禁止把「毒舌/自嘲」等具体性格写进常驻条目。

## 10. 人称策略（踩坑修正版）

- 推荐口径：**「人称与指称随玩家档案与写法——第一/二/三人称皆可，玩家用哪套就跟哪套；未明确时延续前文正在用的人称，不自作主张切换。」**
- 反面教材（实测均被用户推翻）：① 硬性「一律 `{{user}}` 指称、禁『你/我/她』」；② 「默认第三人称限制视角」。**两头钉死都不可取**，做成随玩家可配。
- 附注：人物对白保持自然口语（NPC 不可能喊「user」）。

## 11. ★"现实感限制器"：约束生理反应不夸张 + 跨模型生效

**需求场景**：用户要一道护栏，杜绝"一碰就受不了 / 刚勃起就要射 / 摩擦两下就到顶"的失真反应，要求**参考现实人类生殖器的敏感度与耐受度**，做同等的限制。

**根因**：色情卡默认文风是"感官拉满"，模型（尤其弱指令模型）会为了"爽感"而无限放大反应——它不是在违反规则，是**根本没有一条硬规则告诉它什么叫"合理"**。

### 11.1 规则要写成"可判定的阈值"，不是"要真实一点"

空泛的"请符合现实"完全没用。有效的写法是**条件判定 + 明确阈值 + 反例**：

- **阳具方（男/扶她）射精判定**——列 C1~C4 四个条件（① 持续刺激达较长时长 ② 强度达"激烈"及以上 ③ 自身已处高亢奋态 ④ 忍耐力档位低），要求**至少满足两项**；忍耐力"强/极强"者须**再多满足一项**。明确写"勃起≠濒临射精、被触碰≠失控、单纯摩擦≠致射"。
- **女方高潮判定**——绑定到**已有数值闸门**（如"快感 < 100 时无论描写多激烈一律禁止高潮；< 60 连高潮相关描写都禁止"）。**能挂到变量上的规则最可靠**，因为它可被 schema 兜底、可被状态栏显示。
- **黑名单**（"一碰就湿/刚勃起就射/两下就到顶"逐条列出＝违规）+ **白名单**（写"应激"而非"失控"：呼吸变沉、指节泛白、喉间闷哼，但仍在掌控中）。
- **自检清单**：给模型 5~7 条"输出前逐条自问"，把规则从"知识"变成"流程"。

### 11.2 ★跨模型生效 = 四层冗余注入（单靠世界书条目会被忽略）

实测教训：只把限制器写进一个世界书条目，**DeepSeek / Gemini 这种指令跟随较弱的模型会直接无视**（它们更看重靠近对话、每回合必发的内容）。可靠做法是**同一约束在四个位置冗余注入**，覆盖"必发/贴对话/贴变量"三条路径：

| 层级 | 位置 | 为什么有效 |
|---|---|---|
| ① 世界书条目 | 独立条目（`constant: true`，`insertion_order` 给到最高，排在所有性规则之后） | 承载完整规则正文（阈值/反例/自检），常驻不靠关键词触发 |
| ② 变量更新规则顶部 | `[mvu_update]变量更新规则` 正文最前面加「全局铁律」3 条 | 该条目是 `constant` 且**每回合必读**，且紧贴变量系统 |
| ③ `depth_prompt` | `data.extensions.depth_prompt = {prompt, depth: 4, role: 'system'}` | **贴近对话注入**——弱指令模型最吃这一套（很多人不知道这个字段能用） |
| ④ `description` + `system_prompt` | 角色描述与系统提示末尾追加同一段硬约束摘要 | **每回合必发**，与模型无关，兜底 |

外加可选第五层：`data.post_history_instructions` 写一句"输出前自检"。

要点：
- 四层内容是**摘要 ↔ 全文**的关系，不是复制粘贴四遍（① 详、②③④ 各一两句）。
- 写"**优先级高于文风要求**"、"与『写得刺激』冲突时一律以本约束为准"——模型需要一个明确的冲突裁决规则。
- 加一句"含 DeepSeek、Gemini 等任何模型均须遵守"有时反而有效（点名当前模型会提高遵守率，实测）。
- 交付后提醒用户：这类护栏**改不动就调阈值**（如把"合不拢"的触发次数从 15 调 25），不要重写措辞。

### 11.3 "身体损耗"状态设计：可逆 vs 不可逆分层

同一套思路可用于"长期使用留下的身体变化"（松紧、肿度、色泽变深等）。设计要点：

- **一张表拆成两层**：**可逆层**（肿度、松紧——过夜/禁欲可恢复）与**不可逆层**（色泽沉淀、累计次数——只增不减）。写清各自的恢复条件与"永不回退"标记。
- **与既有变量解耦**：`开发度`（熟练程度）与 `痕迹`（物理损耗）**分开记录、互不覆盖**——可"熟练而紧致"，也可"生涩却已合不拢"。这句写进规则里，防止模型用一者覆盖另一者。
- **给一个 0~100 的"单次承受烈度"**作为派生源：肿度、松紧降档都从它推导，避免每处各写一套判定。
- **不可逆项要敢于真的不可逆**：写明"纵使长年修养也不会褪去"——这是它在叙事上最有价值的地方。
- 与"加速器"联动：体型/道具/对方数值（如扶她精液量、尺寸描述）作为**阈值减半或烈度下限**的乘子，让不同遭遇产生不同后果。
